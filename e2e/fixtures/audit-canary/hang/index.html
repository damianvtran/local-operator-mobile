A page that never settles

Two adversities at once, both real: the main thread is blocked, and an event stream is opened and never closed.

  1. The script below spins forever, so anything the harness evaluates in this page — the readiness probe, the measurement probe, any CDP call that needs the renderer — never comes back.
  2. An EventSource is opened against the relay's session stream, which is a connection that never ends. The static server proxies it, so a shutdown that waits for open connections waits forever.

Neither is a reason for a capture run to hang: the per-cell deadline must fail this cell with a named reason, and the run must terminate and exit non-zero.
